# Code Analyze

根据用户需求深度分析代码，逐步解析执行流程，标注易错点，生成流程图，并将结果写入文件。

## 文件命名

- 分析文件：`docs/analysis-<topic>.md`（kebab-case）
- 同一主题的后续分析追加到同一文件

## 流程

### 1. 需求理解

- 解析用户的代码范围和问题
- 确定分析主题名称
- 检查是否存在同主题的历史分析文件

### 2. 生成分析计划

根据问题复杂度，生成结构化计划：

| 模块 | 文件 | 分析重点 | 执行方式 |
|------|------|----------|----------|
| 模块A | file_a.cpp | 入口逻辑 | [PARALLEL] |
| 模块B | file_b.cpp | 数据处理 | [PARALLEL] |
| 模块C | file_c.cpp | 结果汇总 | [SEQUENTIAL] |

**可并行**：独立模块、不同分支、独立组件
**必须串行**：存在调用链依赖、需要前序分析结果

### 3. 执行分析

- **[PARALLEL]**：Codex sub-agent 同时启动多个 agent
- **[SEQUENTIAL]**：按顺序执行
- 收集结果后合并、去重、生成全局视图

### 4. 详细分析

**执行流程** - 逐步解析：

```
### Step N: [步骤名称]
**代码位置**: `file.cpp:123-130`
**执行内容**: 描述做了什么，涉及的变量和状态变化
```

**易错点标注** - 识别容易理解错误的部分：

```
### N. [易错点标题]
**位置**: `file.cpp:150`
**表象**: 看起来像是...
**实际**: 但实际上是...
**正确理解**: 应该这样理解...
```

常见易错类型：隐式类型转换、指针/引用语义、异步执行顺序、作用域生命周期、运算符优先级、资源所有权转移

**流程图** - 使用 ASCII art（放在 `text` 代码块中）：

```text
┌─────────┐     ┌─────────┐     ┌─────────┐
│  开始   │────▶│ 条件判断 │────▶│  结束   │
└─────────┘     └─────────┘     └─────────┘
```

使用 `┌ ┐ └ ┘ ─ │ ▼ ▲ ► ◄ ├ ┤ ┬ ┴ ┼` 绘制

### 5. 输出结果

文件结构：

```markdown
# <主题> 代码分析

## 分析记录

### [日期时间] - [子主题/问题]

#### 分析目标
[用户的分析需求]

#### 涉及文件
- `path/to/file1.cpp`

#### 执行流程
[逐步分析内容]

#### 易错点
[易错点标注]

#### 流程图
[ASCII 流程图]

#### 总结
[简要总结和关键结论]

---
```

## 规范

1. **分析计划**：包含模块划分、依赖关系、`[PARALLEL]/[SEQUENTIAL]` 标注
2. **并行执行**：单个消息发送多个 sub-agent 调用，等待全部完成后汇总
3. **每个 Step**：说明代码位置、执行内容、状态变化
4. **易错点**：说明表象 vs 实际、为什么容易错、正确理解方式
5. **持续分析**：同一主题追加而非覆盖，用分隔线区分
