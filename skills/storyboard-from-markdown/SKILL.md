# Storyboard From Markdown Skill

## Purpose

Use this skill when the user wants to turn markdown content, or an image/document that can first be summarized into markdown, into:

1. a page-by-page visual summary spec
2. a prompt pack for pure model image generation
3. model-generated storyboard images
4. a compact PDF for sharing

## Inputs

Required:
- A markdown file path, such as `design.md`
- If the user provides only an image or screenshot, first identify and summarize it into a markdown file, then run the normal workflow.

Optional:
- A config JSON file for page filtering, core-page selection, visual style, cover-page behavior, and prompt overrides
- An output directory; if omitted, write beside the input markdown under `storyboard/<doc_stem>/`

## Outputs

The skill produces:
- `parsed_outline.json`: markdown outline parsed into structured sections
- `story_spec.json`: page-by-page generation plan
- `prompt_pack.md`: a readable prompt list for built-in model generation
- `storyboard_run.json`: input/output manifest for process tracking
- `image_manifest.json`: page-to-image traceability manifest after model images are generated
- ordered image files such as `001_cover.png`, `002_architecture.png`, ... when the user asks for a storyboard, deck, or visual output
- original model images preserved under `images/`
- compact JPG copies under `images_jpeg_q95/` by default
- `*_storyboard_compact.pdf`: a compact PDF generated by default

### Completion contract

When the user asks to "generate a storyboard", "make slides", "visualize", "出图", or similar, the task is **not complete** until image-model-generated files and a PDF exist locally. `prompt_pack.md`, `story_spec.json`, local placeholder graphics, HTML, SVG, matplotlib/Pillow/canvas output, screenshots, or any script-rendered PNGs are drafts only and must not be presented as the final storyboard.

### Non-negotiable image generation requirement

- Final storyboard images **must** be generated by the built-in image model.
- Do **not** use local rendering, screenshots, SVG/HTML export, matplotlib, Pillow, canvas, presentation tools, or PDF rasterization as final images.
- Do **not** label locally rendered images as "generated", "rescued", "final", or "complete".
- If the built-in image model is unavailable, stop after producing `story_spec.json` and `prompt_pack.md`, explicitly report that final image/PDF generation is blocked, and do not create a final-looking PDF from local drafts.
- Do **not** switch this skill to API, SDK, CLI, or other fallback image-generation paths. This skill's final-image path is the built-in image model only.

### Output language priority

- Default final storyboard images to Simplified Chinese when the user writes in Chinese, asks for a Chinese version, or the source summary is Chinese.
- For English PDFs or markdown summarized for a Chinese user, translate the page titles and in-image labels into concise Simplified Chinese before generating images.
- Preserve English only for proper nouns, paper titles, model names, product names, API names, metrics, and widely used technical abbreviations such as P99, EC, GC, RTT, CPU, SSD, and RDMA.
- Image prompts may include English style instructions if helpful, but all visible slide text should be Chinese by default.
- If generated Chinese text is malformed, unreadable, or too dense, retry with fewer and shorter Chinese labels. Do not switch the final images to English unless the user explicitly asks.

## Workflow

1. Parse markdown into sections/pages.
2. Detect the document shape and extract the core sections first.
3. Export a prompt pack for each selected page. If Chinese output is preferred, ensure every page title, text hint, and visible-label instruction is Chinese-first before image generation.
4. Use the built-in image model tool to generate images page by page. This step is mandatory for final output. Do not replace it with local rendering, screenshots, SVG, HTML, matplotlib, Pillow, canvas, or other scripted graphics. If the image model tool is not available, stop and report that the storyboard cannot be completed in this session.
5. Copy each image-model output from the model output directory into the storyboard `images/` directory with sortable numeric prefixes.
6. Write `image_manifest.json` mapping each page number to its title, prompt, original generated-image path, final copied path, and generation status.
7. Review the generated images before merging: check for missing pages, blank images, unreadable labels, obvious text overflow, wrong page order, and major mismatch with the source content.
8. Retry only the affected page prompts if a page is blank, malformed, unreadable, or missing a core flow.
9. Merge the final selected model-generated images into a compact PDF by default with `scripts/images_to_pdf.py`; this preserves the original PNG files and uses high-quality JPG copies for the PDF.
10. Verify the PDF page count equals the final image count.
11. Report the final image count, PDF page count, PDF size, compression mode, and key output paths.

## Rules

- Final storyboard images must come from the built-in image model. Local rendering is allowed only as an explicitly labeled draft/debug artifact, never as the final storyboard.
- Never claim storyboard generation is complete if no image-model-generated images were created.
- Never create a final PDF from local drafts as a substitute for image-model output.
- Keep the page order consistent with the markdown structure after selecting core sections.
- Prefer the highest repeated heading level after the title as page boundaries.
- If no repeated section headings exist, fall back to the whole document as one page.
- Use sortable numeric file prefixes: `001_`, `002_`, etc.
- Keep one final image file per selected page. The number of final images must equal the number of pages in `story_spec.json`.
- Always produce a PDF unless the user explicitly asks for images only.
- Default PDF mode is `compact`: preserve original PNG files in `images/`, create high-quality JPG copies in `images_jpeg_q95/`, and merge those JPG copies into `*_storyboard_compact.pdf`.
- If the user explicitly asks for "无损" or "lossless", use `--mode lossless` and explain that the size reduction is usually limited.
- If the user explicitly asks for maximum quality or original assets, use `--mode original`.
- Keep visual style consistent across pages.
- If the markdown explicitly contains text that must appear on the page, include it in the page prompt.
- For Chinese output, keep in-image Chinese text short: prefer 3-6 labels per page, avoid long paragraphs, and translate dense technical wording into plain Chinese.
- For long or mixed-content markdown, extract the core sections first instead of forcing every chapter onto slides.
- Keep each page prompt focused: preserve 3-6 short labels or ideas per page when possible. Long paragraphs and dense technical tables usually produce unreadable images.
- Prefer `selection_mode`, `core_page_target`, `include_titles`, `skip_titles`, and `title_visual_types` in config instead of manual prompt rewriting.
- For long or noisy sections, use `title_hint_overrides` to replace auto-extracted hints with hand-picked points.
- Prioritize the document's thesis, decisions, plans, risks, actions, results, or key flows depending on document type.
- Run the PDF merge step only after the final selected model-generated images exist locally.
- Use the file-path PDF merge path in `scripts/images_to_pdf.py` so compact JPG compression is preserved in the PDF.

## Quality Gate

Before final response, verify:

- `story_spec.json` exists and has the intended page count.
- `prompt_pack.md` exists and includes every selected page.
- Final image directory exists and contains exactly one image per selected page.
- `image_manifest.json` exists and every entry has `page_no`, `title`, `prompt`, `source_image`, `final_image`, and `status`.
- Every `image_manifest.json` page has `status: "generated"` or another clearly image-model-specific status; reject local/script statuses such as `local`, `rendered`, `locally_rendered`, `screenshot`, `svg`, `html`, `matplotlib`, `pillow`, or `rescued`.
- Every page `source_image` points to the original image-model output location, and `final_image` points to the copied storyboard image. Do not use the same locally rendered file as both source and final image.
- `image_manifest.json` includes a non-null `pdf`, `pdf_page_count`, and a `pdf_outputs.compact` entry unless the user requested a different PDF mode.
- At least the cover, one architecture/flow page, and one risk/test/summary page have been visually inspected.
- Images are not blank and key text is not obviously cut off or overlapping.
- When Chinese output is preferred, inspected pages use Chinese titles and Chinese labels, except for allowed proper nouns and technical abbreviations.
- A PDF exists by default, and its page count equals the final image count.
- The final response includes the PDF size and, when compact mode is used, the approximate size reduction versus the original images or original PDF if available.

If any check fails, fix or retry before responding. If the issue cannot be fixed, explicitly state what is missing and why.

## Image manifest format

After model generation, write a manifest similar to:

```json
{
  "model_generation_required": true,
  "final_image_count": 3,
  "pdf": "storyboard/design/design_storyboard_compact.pdf",
  "pdf_page_count": 3,
  "pdf_outputs": {
    "compact": {
      "pdf": "storyboard/design/design_storyboard_compact.pdf",
      "mode": "compact",
      "page_count": 3,
      "source_image_count": 3,
      "prepared_dir": "storyboard/design/images_jpeg_q95",
      "jpeg_quality": 95,
      "source_images_size_mb": 13.36,
      "prepared_images_size_mb": 4.11,
      "pdf_size_mb": 5.1
    }
  },
  "pages": [
    {
      "page_no": 1,
      "title": "Cover",
      "prompt": "...",
      "source_image": "/Users/.../.codex/generated_images/.../ig_xxx.png",
      "final_image": "storyboard/design/images/001_cover.png",
      "status": "generated"
    }
  ]
}
```

Use the generated-image source path reported by the image model tool. Copy generated images to the final image directory; do not move or delete originals. If no image-model source path exists for a page, that page is not final.

## How to run

### Install dependencies

Install local Python dependencies before running scripts that read or merge image files:

```bash
pip install -r requirements.txt
```

`run_pipeline.py` uses only the standard library, but `images_to_pdf.py` requires `Pillow` and `reportlab`.

### Prepare storyboard assets

```bash
python scripts/run_pipeline.py \
  --input-md example/design.md \
  --config example/config.example.json
```

For a more generic markdown summary:

```bash
python scripts/run_pipeline.py \
  --input-md example/general.md
```

This produces:

- `parsed_outline.json`
- `story_spec.json`
- `prompt_pack.md`
- `storyboard_run.json`
- a suggested compact PDF path in `storyboard_run.json`

### Merge images into PDF

After using the built-in image model to generate pages and copying them into `<doc_dir>/storyboard/<doc_stem>/images/`, generate the default compact PDF:

```bash
python scripts/images_to_pdf.py \
  --input-dir example/storyboard/design/images \
  --output example/storyboard/design/design_storyboard_compact.pdf
```

Other modes:

```bash
# Maximum quality, larger file
python scripts/images_to_pdf.py --mode original \
  --input-dir example/storyboard/design/images \
  --output example/storyboard/design/design_storyboard_original.pdf

# Lossless PNG optimization, usually limited size reduction
python scripts/images_to_pdf.py --mode lossless \
  --input-dir example/storyboard/design/images \
  --output example/storyboard/design/design_storyboard_lossless.pdf
```

The script updates `image_manifest.json` automatically when it exists next to the `images/` directory. Use `--manifest <path>` if the manifest is elsewhere.

## Notes for the coding agent

- Ask for confirmation only if the input markdown is missing or empty.
- If the user provides an image/screenshot instead of markdown, identify its content, write a markdown summary, then run this skill normally.
- Default to pure built-in image-model generation. Do not switch to API, SDK, CLI, or any other image-generation path inside this skill.
- Do not substitute image-model generation with local scripted rendering. If you create a local draft to inspect layout, clearly label it as draft, keep it outside the final `images/` directory, and still generate the final pages with the built-in image model.
- If image-model generation is unavailable, do not "finish" the storyboard. Leave the task as blocked with the prompt pack ready for image-model generation.
- Treat this as a markdown-to-core-information skill, not a design-doc-only skill.
- If the markdown is long or full of appendices, references, or logs, extract core pages first.
- Use `selection_mode=auto` for general use, `selection_mode=core` for tighter summaries, and `selection_mode=all` only when the user explicitly wants every section.
- If one page has a misleading inferred visual type, fix it with `title_visual_types`.
- If auto-extracted hints are noisy, fix that page with `title_hint_overrides`.
- If generated images have unreadable text, hallucinated labels, or broken diagrams, simplify that page's prompt and retry just that page.
- If Chinese output was requested or implied, treat English-dominant generated pages as failed pages and retry them with stronger Chinese-visible-text instructions.
- Prefer diagrams, cards, timelines, matrices, and flow layouts over dense text slides.
- Keep intermediate JSON and the prompt pack even if image generation is interrupted.
- In the final response, include whether model images were generated, how many images exist, the PDF page count, PDF size, compression mode, and the output paths.
