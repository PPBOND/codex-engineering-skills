# 会话采集与证据

## 完整性优先，读取按需

先发现并使用应用提供的 `list_threads`、`list_archived_threads`、`read_thread`。按返回的游标读完所需分页，覆盖本地及可访问的已连接主机；“所有会话”也包含可访问的 ChatGPT 活跃和归档会话。列表可能只返回最近若干条，列表数量不是总量证明。获取所有候选后再按实际消息/事件时间筛选；不得仅按创建时间或最后更新时间选会话。

保留来源提供的会话原名、ID、主机、类型、周期内首末活动、纳入理由、读取范围。解析异常、不可访问主机、云端缺页等进入覆盖缺口。没有查全时写“已覆盖的可访问范围”，不要声称全账户无遗漏。

## 本地记录补全

应用列表不足以覆盖长历史时，在实际用户配置目录下发现 `sessions`、`archived_sessions` 和任务索引。不要写死用户绝对路径或 `state_5.sqlite` 等版本化文件名。

- 本地文件查找/读取遵循当前文件工具规则；批量结构化 JSONL 解析可用小型只读脚本。复用已有解析器前检查参数、时间过滤与输出范围，禁止直接运行硬编码旧周期的脚本。
- 老目录可以包含本周续接记录：枚举候选 rollout，再过滤每一条记录的时间戳。文件创建/修改时间、目录日期只能加速定位，不能证明是否属于周期。
- 以 `session_meta.payload.id` 等实际会话身份合并恢复/续接文件，去重重复消息；保留原文件路径、行号和消息时间。
- 用真实用户请求和助手工作内容判断有效活动；AGENTS、环境注入、自动摘要、系统说明、纯状态更新不是新成果。压缩摘要可能重复更早的工作，须追溯本期实际增量。
- 子代理结果合并到父任务，保留来源，不重复记独立成果。仅状态更新的历史会话单列。
- 消息和工具事件结构可能不同；尤其 ChatGPT 不一定有 Codex 的 `phase`。兼容实际观察到的结构，未提取到工具结果不代表没运行测试。
- 索引仅用于发现和补充标题；不要假定其创建时间就是第一次对话时间。SQLite 只读打开，查询前查看实际表结构，不修改运行中数据库。
- 精简输出有助于浏览，但截断或省略长答复不能作为完整性依据；对入选成果和矛盾项补读原始记录。

## 证据账本与去重

每个合并工作项至少保留以下信息，可用 JSON 或表格，不强制额外格式：

| 字段 | 用途 |
|---|---|
| 标题、项目、会话 ID | 去重、追溯、展示 |
| 工作类型、具体交付物 | 区分代码改动、工具优化、测试、设计、调研、环境支持；标题能直接说明做了什么 |
| 输入/对象、实际动作、输出/行为 | 用于写清工具如何使用、功能改变了什么；不适用的字段不强凑 |
| 周期内实际工作 | 排除旧成果重复计入 |
| 已确认结果、贡献与价值 | 正文摘要 |
| 实现 / 验证 / 提交 / 发布状态 | 避免“完成”混淆 |
| 测试/性能日期、版本、环境、样本、指标 | 解释结果适用范围 |
| 验证对象 | 分清测试的是工具、日志、接口、恢复还是性能，防止跨对象扩大结论 |
| 失败、修复、代价、待办 | 风险和下一步 |
| 来源路径/行号或消息时间/链接 | 证据定位 |

对冲突证据按版本和时间排列，必要时补读相关测试日志、报告或 Git 只读状态。终端输出、最终回复和当前工作树不是相互替代关系。当前状态不得覆盖当期事实；后来修复的当期失败可以写“阶段失败 → 已修复”。

正文只呈现必要证据摘要，附录按会话列出“本期做了什么、状态、对应工作项、来源”。不把完整私聊或工具输出复制进汇报；不在工具输出中倾倒含凭证的原始历史。
